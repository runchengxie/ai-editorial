# Article daily and weekly editions

[简体中文](magazine.zh-CN.md)

The article magazine is generated by this engine and displayed by [ai-editorial-pages](https://github.com/runchengxie/ai-editorial-pages). The original v1 source-link endpoint remains stable. The separate v2 magazine library carries bilingual daily/weekly articles, numbered feature paragraphs, related updates, short briefs, dated outlook and source references.

## Evidence and generation

The daily packet covers24hours, explicitly expanding to72hours on quiet days. The weekly packet covers the previous complete Monday–Sunday in Asia/Shanghai. Enabled free RSS/HTML sources are read through the existing guarded collectors. Direct article extraction uses `paidFallback: false`; no Jina/paid social provider is enabled. Thin evidence stays short; original bodies never enter the public payload.

Codex is invoked non-interactively with the existing local ChatGPT login, read-only sandbox, user-config isolation, disabled shell/browser/apps/plugins/hooks/image tools, a structured output schema and a ten-minute deadline. Only bounded public evidence is provided on stdin. The child environment is allowlisted; GitHub/database/API credential variables are not forwarded. No login material is copied to GitHub. Installed CLI/model access must remain valid; this route consumes Codex subscription quota and is not promised to be an unlimited/free API.

Calls use the existing PostgreSQL receipts and `codex-cli` budget. Initial deployment allows2/minute,3/hour,3per rolling24hours, and preserves operator changes. The same persisted evidence packet yields the same logical request and reuses a received answer. An uncertain CLI outcome stops that issue, including a changed-input attempt, until operator review. No immediate retry is performed. Narrative anchors must match cited evidence; numeric claims must be supported by those quotes or the cited source's title/exact product identifiers, with value-preserving million/billion↔万/亿 conversion. This is a sanity/traceability check, not semantic fact verification or human review. Unsupported output is not published.

`modules/editorial-magazine` owns the implementation. Raw packets, quote anchors and CLI diagnostics stay under DATA_ROOT/ai-editorial/magazine and PostgreSQL. Only the projected public library is published. Source-linked prose is paraphrased; screenshots and artwork from the reference article are not copied. Dates in outlook require exact dated source evidence, retain planned wording, and may extend at most365days beyond the issue period.

## Local scheduled worker

The stable source release is DATA_ROOT/ai-editorial/releases/<checked-main-sha>/. Authoritative configuration is CONFIG_ROOT/projects/ai-editorial/magazine.env, mode0600; it refers to the designated existing GitHub credential file and Codex home, without duplicating either credential. PostgreSQL uses a separate project data directory and owner-only Unix socket with peer authentication, not the disposable evaluation cluster.

After exact-main CI passes, run `scripts/magazine/install-local.ts` from the clean primary engine checkout with explicitly resolved CODE_ROOT, DATA_ROOT, CONFIG_ROOT, MAGAZINE_PG_BIN and MAGAZINE_PG_LIB (stable PostgreSQL18 paths). The installer verifies the main checks, archives an immutable release, installs dependencies, migrates a dedicated database, sets an initial quota budget and creates only `ai-editorial-postgres.service`, `ai-editorial-magazine.service` and `ai-editorial-magazine.timer`. Existing unmanaged units/nonempty unknown databases are refused.

Start the magazine service once and verify its publication before enabling the timer. The timer targets08:27Shanghai daily and catches up after a missed run while the user service manager is available. It creates a daily issue and the latest complete weekly issue when needed. This machine must be running with the data drive mounted and a valid Codex login. The website remains on GitHub Pages when the machine is offline; generation dates stay visible and invalid/stale builds preserve the previous site.

```sh
systemctl --user start ai-editorial-magazine.service
systemctl --user status ai-editorial-magazine.service
journalctl --user -u ai-editorial-magazine.service -n80
systemctl --user enable --now ai-editorial-magazine.timer
```

Do not release unknown receipts automatically. Inspect the private response/receipt first and use the project's existing recovery conventions. To stop generation, disable the timer or set MODEL_CALLS_ENABLED=false in the authoritative worker configuration. Never run production from a task worktree or temporary PostgreSQL binary. Back up the dedicated PostgreSQL/data directory before replacing its runtime; restoring a lost receipt ledger must not blindly resubmit uncertain calls.

## Public data and reader

The fixed GitHub release container `magazine-current` holds immutable `magazine-<sha256>.json` assets. Its JSON body is the atomic manifest pointer (schemaVersion2, asset, sha256, producerRevision, generatedAt). Upload is verified before the pointer changes; old immutable assets remain available to a concurrent reader. A publication then dispatches the reader workflow. A failed or uncertain remote write is queried before any retry; dispatch itself is not retried in the same invocation.

The reader independently validates the manifest, payload digest, all source references, dates and freshness. It publishes daily/weekly pages, issue RSS and inline-styled HTML exports. The active library retains up to30daily and12weekly editions. Raw evidence, quote anchors, model credentials and internal workbench notes are not exported. The release tag is a stable data container, not a claim that every asset uses its original tag commit; producerRevision records the actual checked source revision.

## Validation

Run root typecheck, built dynamic-app/web/backend checks, module tests and the reader's contract/browser suites. Model tests use local stubs; a real CLI evaluation must use its own data/database and explicitly enabled quota budget. Record producer/reader revisions, corpus, receipts, public/private projection and desktop/mobile screenshots under the external task evaluation directory. Publication requires both latest daily and weekly editions.
