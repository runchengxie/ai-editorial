# Article daily and weekly editions

[简体中文](magazine.zh-CN.md)

The article magazine is generated by this engine and displayed by [ai-editorial-pages](https://github.com/runchengxie/ai-editorial-pages). The original v1 source-link endpoint remains stable. The separate v2 magazine library carries bilingual daily/weekly articles, numbered feature paragraphs, related updates, short briefs, dated outlook and source references.

## Evidence and generation

The daily packet covers24hours, explicitly expanding to72hours on quiet days. The weekly packet covers the previous complete Monday–Sunday in Asia/Shanghai. Enabled free RSS/HTML and GitHub release JSON sources are read through the existing guarded collectors. Direct article extraction uses `paidFallback: false`; no Jina/paid social provider is enabled. Thin evidence stays short; original bodies never enter the public payload.

Codex is invoked non-interactively with the existing local ChatGPT login, read-only sandbox, user-config isolation, disabled shell/browser/apps/plugins/hooks/image tools, a structured output schema and a ten-minute deadline. Only bounded public evidence is provided on stdin. The child environment is allowlisted; GitHub/database/API credential variables are not forwarded. No login material is copied to GitHub. Installed CLI/model access must remain valid; this route consumes Codex subscription quota and is not promised to be an unlimited/free API.

Calls use the existing PostgreSQL receipts and `codex-cli` budget. Initial deployment allows2/minute,3/hour,3per rolling24hours, and preserves operator changes. The same persisted evidence packet yields the same logical request and reuses a received answer. An uncertain CLI outcome stops that issue, including a changed-input attempt, until operator review. No immediate retry is performed. Narrative anchors must match cited evidence; numeric claims must be supported by those quotes or the cited source's title/exact product identifiers, with value-preserving million/billion↔万/亿 conversion. This is a sanity/traceability check, not semantic fact verification or human review. Unsupported output is not published.

`packages/editorial-magazine` owns the implementation. Raw packets, quote anchors and CLI diagnostics stay under DATA_ROOT/ai-editorial/magazine and PostgreSQL. Only the projected public library is published. Source-linked prose is paraphrased; screenshots and artwork from the reference article are not copied. Dates in outlook require exact dated source evidence, retain planned wording, and may extend at most365days beyond the issue period.

## Manual evaluation (automation paused)

Scheduled generation and publication are paused by owner request. The local magazine timer must remain disabled; both repositories keep manual GitHub workflows, with no cron or successful-check publication trigger. Existing Pages content remains available. A CI check does not collect news, call Codex or deploy new content. Installing a worker does not enable its timer.

The reusable scripts are committed here; private inputs, receipts and results stay outside Git. Resolve `CODE_ROOT`, `DATA_ROOT` and `CONFIG_ROOT` using the workspace launcher before these commands.

```sh
# Pause/check the local scheduler; pausing does not stop an already running job.
systemctl --user disable --now ai-editorial-magazine.timer
systemctl --user is-active ai-editorial-magazine.service

# Free collection only: does not generate prose, modify the public library or publish.
# The existing env file optionally supplies the designated GitHub token-file path.
node --env-file="$CONFIG_ROOT/projects/ai-editorial/magazine.env" scripts/magazine/inspect.ts --kind both

# Explicitly generate both editions using the installed stable worker and existing quota.
# Writes the saved private library, but does not publish it or enable automation.
node scripts/magazine/manual.ts generate

# A separate explicit action publishes the saved library and dispatches the reader.
node scripts/magazine/manual.ts publish
```

`inspect.ts` defaults to both editions; `--kind daily|weekly` narrows it and `--at <ISO timestamp with timezone>` permits a historical selection window. It writes dated, private packets and `summary.json` under `DATA_ROOT/ai-editorial/evaluations/magazine-inspect-*/`, including actual usable evidence counts, sources, audiences, evidence levels and titles. This is a network collection operation, not a mock or a prediction of final story counts. Raw packets must not be committed or uploaded as website content. The script never imports model generation or publication.

`manual.ts` shows help without arguments. It reads the existing authoritative config and launches the installed immutable release, never production code from the current worktree. Generation consumes the existing Codex budget; exhausted, pending or uncertain receipts must be investigated rather than bypassed. If generation fails, do not publish an assumed new result: inspect the receipt and the saved library timestamps. Publishing also requires fresh v1 compatibility data: manually dispatch `daily-pages.yml` with `mode=refresh` in the engine on checked main first when needed; it does not use a model. Then publish the magazine, or manually dispatch `pages.yml` in the reader. Data freshness and exact-main checks still apply, so reactivation after a long pause needs fresh data before deployment.

Only after an explicit decision to resume scheduled operations:

```sh
systemctl --user enable --now ai-editorial-magazine.timer
systemctl --user list-timers ai-editorial-magazine.timer
```

The retained timer definition targets 08:27 Shanghai; `Persistent=true` may immediately catch up a missed run when enabled. These commands are instructions for later, not part of setup or this evaluation. Cloud refreshes remain manual unless their schedules are deliberately restored in a reviewed code change. To keep everything paused, do not run `enable`, `generate`, `publish` or dispatch a publication workflow.

## Public data and reader

The fixed GitHub release container `magazine-current` holds immutable `magazine-<sha256>.json` assets. Its JSON body is the atomic manifest pointer (schemaVersion2, asset, sha256, producerRevision, generatedAt). Upload is verified before the pointer changes; old immutable assets remain available to a concurrent reader. A publication then dispatches the reader workflow. A failed or uncertain remote write is queried before any retry; dispatch itself is not retried in the same invocation.

The reader independently validates the manifest, payload digest, all source references, dates and freshness. It publishes daily/weekly pages, issue RSS and inline-styled HTML exports. The active library retains up to30daily and12weekly editions. Raw evidence, quote anchors, model credentials and internal workbench notes are not exported. The release tag is a stable data container, not a claim that every asset uses its original tag commit; producerRevision records the actual checked source revision.

## Richer daily and weekly coverage

Candidate limits are30 daily/60 weekly, with weighted finance/development/general rotation, per-source/publisher caps and AI/data-workflow filters for broad feeds. The first12/20 candidates retain at most6000 characters each; others retain1400, bounding private text at97200/176000 characters. Thin excerpts outside the feature window can receive up to4/8 additional free page reads, for at most16/28 daily/weekly reads. Research abstracts and existing full bodies receive no extra read. Text caps stay unchanged.

Daily targets7–9 features and15–20 briefs; weekly targets10–12 features and20–25 briefs. Thin material produces fewer items, never padding. The v2 shape is unchanged, with bounds of12 features,25 briefs and60 source references. Deploy the more permissive reader before publishing expanded producer output; retain old issues. Numeric validation supports percent/per cent↔% and exact three-part versions; it is not semantic fact verification.

## Single-edition pilot

For a private acceptance draft, use the saved, bounded evidence packet without recollecting sources or touching the public library. After this code is integrated and its exact main revision is checked, run from clean main:

```sh
node --env-file="$CONFIG_ROOT/projects/ai-editorial/magazine.env" scripts/magazine/pilot.ts --packet "$DATA_ROOT/ai-editorial/evaluations/<task>/pilot.packet.json" --out "$DATA_ROOT/ai-editorial/evaluations/<task>/draft-1"
```

Inputs/output must stay under the project's external evaluations directory; output must be new. The command generates exactly one daily/weekly edition using the existing receipt ledger, quota and saved request identity. It never changes a budget, publishes, edits the canonical public library or enables automation. No arguments show help. Private outputs include `library.json`, bilingual Markdown, CLI diagnostics and an acceptance manifest with counts, source revision, input digest and receipt ID. Structural, date, boundedness, exact-quote and numeric checks must pass before export. Editorial review remains pending until usefulness, distinct events, wording and source support are inspected. A failed or uncertain receipt must be examined and recovered through the existing receipt conventions; do not create a new output name to evade budget or unknown-outcome guards. Generating from the same saved packet may reuse an already received response.
