# Article-style daily and weekly editions

The user approved both article-style daily editions and a long-form weekly edition, modeled on their saved AI Weekly HTML. They selected the locally logged-in Codex CLI non-interactive mode instead of a model API. A read-only structured-output preflight succeeded on2026-11-17 using codex-cli0.167.0 and the existing gpt-6.1-sol/low setting. The test fixture was fictional and must never be published.

Keep the two-repository boundary. ai-editorial owns evidence collection, content generation, source validation, issue history and publication; ai-editorial-pages owns reading layout, navigation, locale text, RSS and downloadable publication HTML. The existing v1 source-link feed stays stable. A new v2 magazine library carries bilingual issue titles/leads, overview summaries, numbered feature paragraphs, related short updates, briefs, dated outlook and source references. Original bodies and private quote anchors stay local. Images are optional; do not fabricate screenshots or reuse reference-article artwork.

A daily issue covers the last24hours, with an explicit72hour window only when needed for a quiet day; a weekly issue covers the previous complete Shanghai Monday–Sunday. First run may generate both. Normal local scheduling: daily08:27 Shanghai, plus weekly on Monday. Codex receives only a bounded evidence packet from public configured sources and direct free article reads, never project credentials. It runs read-only, without shell/browser/apps or user configuration, with an output schema and a deadline. Generated paragraphs must cite known sources and exact private evidence quotes; unsupported numeric claims and invented future dates are rejected. This is automatic source-linked synthesis, not a claim of human fact verification.

Codex quota usage goes through the existing database receipt/budget mechanism. Use a dedicated project PostgreSQL instance and durable data/configuration roots, not an evaluation database. Configure at most3new calls/day, with cache reuse and no immediate retry after uncertain outcomes. No model login material is copied to GitHub. A stable release and user timer generate content locally; the publisher uploads an immutable hash-named public JSON asset to a fixed release container, then atomically updates its manifest pointer and dispatches the reader. The reader validates hash/schema/freshness before publishing. Failed generation keeps previously published editions.

Reference typography: narrow white article column,15px/30px body, generous paragraph spacing,22px section headings,20px numbered news headings, navy accents and fine rules. Daily and Weekly share this layout, with an overview followed by features, related items, briefs and outlook. English remains default and Chinese selection persists. Source links are visible. Provide standalone inline-styled HTML for editorial reuse.

Alternatives: model login on hosted Actions would require credential transfer; browser-only writing would prevent reliable scheduling; direct API integration contradicts the user's selected trial. Chosen: local Codex worker plus existing GitHub-hosted reader. Local generation depends on this machine being running/logged in with valid Codex access; catch-up timers and visible generation dates make that limit explicit.
