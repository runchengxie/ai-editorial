# 本机任务升级

[English](runtime-upgrade.md)

本机刊物任务直接使用Node.js和PostgreSQL，与静态网站独立。安装检查通过的不可变版本会更新私有版本指针和受管理的用户服务，不启用生成、发布或定时器。安装器现在使用 `npm ci --omit=dev`，只装任务需要的运行依赖，不装Vite等网页开发工具。CI验证这一依赖集可以导入生成模块，并审计生产依赖树。

## 升级前

要求准确源码版本的push-main检查通过、主目录干净、专用数据库与集群归属明确，并使用稳定的PostgreSQL程序及库路径。定时器保持禁用，生成服务保持停止。记录旧版本、服务定义、回执数量、预算和公开数据摘要。私有配置放CONFIG_ROOT，备份及结果放DATA_ROOT并限制所有者访问。

使用匹配版本的pg_dump备份，在独立测试库恢复、执行待应用迁移，并验证数据保留和完整备份恢复。修改生产前检查数据库依赖。不改写迁移历史，不把上游SQL注释当作本分支授权。

## 0169迁移

11月18日演练完成数据库备份和恢复，在独立副本删除 `selected_ledger.visible_at`，并证明完整恢复可找回旧结构。该表0行，4条回执和尝试记录完整保留。已记录的依赖只有默认值、非空约束和索引。所有者在演练后单独批准了删列及任务升级，11月18日的安装已经执行0169。该列及索引现已移除，原有4条回执和尝试记录完整保留，任务记录保留备份位置和校验值。后续仅调整目录的版本不需要重新执行该迁移。

执行后，仍读取该列的旧代码不能单独回退。回滚需要在停止生成的状态下，协调旧不可变版本、私有配置与服务定义，以及完整数据库恢复。不能把旧回执账本覆盖到新调用上。备份后若有活动，回滚前先核查。

## 安装与检查

从干净main运行既有 `scripts/magazine/install-local.ts`，明确传入CODE_ROOT、DATA_ROOT、CONFIG_ROOT、MAGAZINE_PG_BIN和MAGAZINE_PG_LIB。安装器核对main检查、归属及迁移记录，保留已有预算，定时器由所有者另行决定。凭据不复制进源码或GitHub。

安装后验证配置版本、信源文件路径与数量、运行模块导入、回执和尝试次数、预算及结构。确认定时器仍禁用、生成服务仍停止。帮助命令和模块导入检查关闭外部操作，不用实际生成充当冒烟测试。实际升级结果与本操作说明分开记录。

以后明确生成和发布见[刊物操作](magazine.zh-CN.md)，仍未修复的开发依赖公告见[依赖安全](dependency-security.zh-CN.md)。
